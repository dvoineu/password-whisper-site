            LAYER 01 · KEY DERIVATION (KDF)
            
Argon2id (IETF RFC 9106)Argon2id (стандарт IETF RFC 9106)

            
Your Master Password is normalized (Unicode NFC) and stretched through memory-hard Argon2id with a random 128-bit salt from SecRandomCopyBytes. Even a specialized GPU cluster manages only ~25,000 guesses/sec — making a 4–5 word passphrase take centuries to crack.Мастер-пароль нормализуется (Unicode NFC) и проходит через памятеёмкий Argon2id со случайной 128-битной солью (SecRandomCopyBytes). Даже специализированный GPU-кластер даёт ~25 000 попыток/с, поэтому фраза из 4–5 слов подбирается столетиями.

            
RFC 9106 Argon2id · memoryKiB=32768 (32 MiB) · t=3 · p=4 · 16B salt · Verified vs RFC 9106 §5.3

          


          

            LAYER 02 · ENVELOPE ENCRYPTION & HKDF
            
Dual-Slot VaultKey + Domain SeparationКонвертное шифрование и разделение ключей

            
A random 256-bit VaultKey (DEK) is wrapped separately by your Master KEK and your offline Recovery Key (PS1-XXXX-…). Rotating your Master Password or Recovery Key happens in O(1) with a fresh salt. Subkeys for items, blobs, and drafts are derived via HKDF-SHA256.Случайный 256-битный VaultKey обёрнут независимо мастер-ключом и аварийным ключом восстановления (PS1-XXXX-…). Смена мастер-пароля идёт за O(1) с новой солью, а подключи для записей, файлов и черновиков разделены через HKDF-SHA256.

            
MasterPassword → KEK → VaultKey(256b) → HKDF-SHA256 → ItemSubkey / BlobSubkey / DraftSubkey

          


          

            LAYER 03 · AUTHENTICATED PER-OBJECT STORAGE
            
Apple CryptoKit AES-256-GCM + Strict AADПо-объектное AES-256-GCM + строгий AAD

            
Every login (items/<uuid>.item.enc), redacted screenshot, and .p8/.pem file (blobs/<sha256>.blob.enc) gets a fresh 96-bit nonce and cryptographically binds vaultID, objectID / SHA-256, and revision metadata via AAD.Каждая карточка, скриншот и файл .p8/.pem шифруется уникальным 96-битным nonce, 128-битным auth-тегом и привязкой AAD к vaultID, objectID / SHA-256 и ревизии — подмена или перестановка файла невозможны.

            
AES-256-GCM · 96b nonce · 128b tag · AAD("sentinel.item.v1|vaultID|itemID") · SHA-256 verify

          


          

            LAYER 04 · RAM, CLIPBOARD & PIXEL BURN-IN
            
Zero Swap Leakage & Protected ClipboardЗащита RAM, буфера обмена и изображений

            
SecureBytes pins key pages via mlock() and wipes buffers using compiler-safe memset_s(). Screenshots & secret files decrypt strictly in RAM via withDecryptedBlob. ClipboardGuard blocks Universal Clipboard/Handoff and clipboard history tools, clearing secrets after 25s.SecureBytes блокирует выгрузку ключей в swap (mlock) и затирает память через memset_s. Снимки и файлы расшифровываются только в RAM без temp-файлов; ClipboardGuard блокирует Handoff и историю буфера, очищая пароль через 25 с.

            
mlock + memset_s · .currentHostOnly / .localOnly · ConcealedType · Pixel Burn-in + 0 EXIF

          


          

            LAYER 05 · HARDWARE BIOMETRICS
            
Data Protection Keychain without PIN FallbackАппаратная биометрия без отката на PIN

            
Biometric unlock stores the key exclusively on-device (ThisDeviceOnly) with .biometryCurrentSet. Adding a new fingerprint or face immediately invalidates the stored key, and cancelling biometrics always requires your Master Password — never the OS passcode.Ключ быстрой разблокировки хранится только на этом устройстве (ThisDeviceOnly) с привязкой .biometryCurrentSet. Добавление нового отпечатка или лица аннулирует ключ, а при отказе биометрии всегда нужен мастер-пароль.

            
kSecAttrAccessibleWhenUnlockedThisDeviceOnly · .biometryCurrentSet · localizedFallbackTitle=""

          


          

            LAYER 06 · ANTI-PHISHING & SANDBOX ISOLATION
            
Strict Domain Matching & Local Browser BridgeАнтифишинг, App Sandbox и локальный мост

            
URLMatcher enforces Public Suffix List matching, exact port/path context, and refuses to serve HTTPS credentials over plaintext HTTP (except localhost). Desktop extensions talk via sandboxed Native Messaging (stdio) with zero open TCP ports and 20s single-use Open & Fill leases.URLMatcher сверяет домен по Public Suffix List, учитывает порт и путь и запрещает подстановку HTTPS-паролей на HTTP. Браузерные расширения работают по локальному stdio в App Sandbox без открытых сетевых портов.

            
App Sandbox = true · PSL + HTTPS strict · Closed Shadow DOM · 20s origin-bound lease

          


          

            LAYER 07 · CONTINUOUS ENGINEERING VERIFICATION
            
How security is continuously tested before every releaseКак мы проверяем безопасность в коде перед каждым релизом

            
Every release passes automated unit & integration test suites across all 7 Swift modules: byte-for-byte IETF RFC 9106 Argon2id test vectors, negative tamper tests verifying tamperedOrCorruptedData when a single bit, UUID, AAD, or revision hash is altered, SecureBytes wipe assertions, deterministic offline conflict merge tests, URLProtocol tests proving zero HTTP redirects and zero direct HIBP fallback, 100% Clean-Room Swift 6 without third-party tracking SDKs, plus Apple App Review & App Sandbox signing checks.Каждый релиз проходит автоматизированные тесты по всем 7 Swift-модулям: побайтовая сверка Argon2id с официальным вектором IETF RFC 9106, негативные тесты на подмену 1 бита / UUID / AAD / ревизии (tamperedOrCorruptedData), тесты затирания SecureBytes, тесты детерминированного слияния конфликтов, тесты URLProtocol на отказ от HTTP-редиректов и прямых запросов к HIBP, 100% Clean-Room Swift 6 без сторонних трекинг-SDK и проверка Apple App Review / App Sandbox.

            
SentinelCryptoTests (RFC 9106) · SentinelStorageTests · SentinelSyncTests · SentinelSystemTests · Apple App Review
